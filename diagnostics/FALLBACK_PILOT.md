# Одноразовый fallback_pilot: math_d15

Только диагностическая подготовка. Настоящий запрос требует отдельного разрешения.
Исходный A1 остаётся неуспешным; новый режим не выдаёт успешную квитанцию A1 и
не меняет допуск A2. Других задач, a1_limit, повторов A1 и перехода к A2 нет.

## Условия и прогноз

- Только development math_d15, модель qwen3.6-35b-a3b-noreason.
- Один новый HTTP-запрос, max_tokens=512, без retries и redirects.
- Совокупный BUDGET=900. История: ack 35/10+11=14.5, math 53/10+7=12.3.
- Исторические 26.8 восстанавливаются через reserve/settle BudgetManager;
  этот же объект используется workflow. Доступно 873.2.
- Оценка входа 1880, резерв 1880/10+512=700. С историей 726.8 из 900.
- Это эвристическое резервирование, не гарантия удалённого потолка списания.

Проверяются просмотренные LIVE-квитанции A1/A1_resume и постоянные A1 intent/result:
хеши, источник, модель, endpoint, runtime, параметры, положительные диагностики
math и достоверный usage. Предоставленный resume должен совпадать с журналом.
Хеши исторических версий зафиксированы явно, без общего обхода проверки.
Для нового кода обязательна свежая passing offline-квитанция с fingerprint,
включающим fallback_pilot.py. Неясная история, неверный endpoint/ключ/BUDGET или
непоместившийся резерв останавливают запуск до HTTP. Это проверка целостности
известной локальной истории, не подпись провайдера.

## Исполнение и измерения

Переиспользуется run_tasks_diagnostic: реальный production workflow openJiuwen,
локальная попытка, штатные prepare/промпт, шлюз, JSON-парсер, семантический
валидатор, локальный исполнитель и атомарный save_answer. Production-файлы
не меняются. Python модели не исполняется. Эталон и просмотренный план доступны
только оценщику/наблюдателю в памяти, не task.json и не сообщениям модели.

Диагностический шлюз отклоняет несовпадающую указанную модель и неожиданный
reasoning_content до разбора/исполнения плана. Подтверждённый usage учитывается.
Авторизация, 429, timeout и unknown usage не повторяются; неопределённый расход
удерживает резерв и замораживает менеджер.

Отчёт раздельно показывает HTTP/внешний JSON, внутренний JSON, схему плана,
решение production-валидатора и безопасный код отказа, независимую оценку смысла,
поддерживаемые операции, фактическое исполнение, answer.txt/права/правильность,
finish_reason, usage, новый/суммарный расход и время задачи.

operation_order_or_evidence соответствует объединённой проверке production:
нельзя без доказательств уточнять, виновата операция или цитата. Неизвестная
семантика остаётся not_assessed. operations_supported означает наличие операций
в поддерживаемом наборе, а не доказательство прохождения runtime-лимитов.
При unknown usage новая стоимость имеет null, не якобы бесплатный ноль.

## Журнал и артефакты

Переиспользуются state_directory/write_once из A1_resume. Новый постоянный
журнал diagnostics/.fallback-pilot-state/ (0700), файлы 0600, исключён из Git.
Перед workflow неизменяемый intent создаётся O_EXCL/O_NOFOLLOW; fsync файла и
каталога завершаются до возможного HTTP. Любой существующий файл блокирует повтор,
включая другой output, конкурирующий процесс и неопределённый исход. Отдельный
result сохраняется тем же способом. Сброса нет. При прерывании без результата
нужна ручная проверка, не повтор. Старый журнал A1 открывается только для чтения.
Гарантия требует сохранения общего журнала; запуск другой копии проекта с новым
журналом не является продолжением и не разрешён автоматически.

Output — новый приватный каталог 0700: report.json/report.md (0600), одна рабочая
копия tasks/math_d15 и при успехе настоящий answer.txt (0644). Сохраняются metadata
и результат независимого benchmark.compare. Ключи, headers, provider errors,
полные prompts/ответы/планы модели не сохраняются. Дополнительных LLM-вызовов нет.
Режим не входит в allowlist конкурсного Docker-образа.

## Офлайн-preflight

```bash
.venv/bin/python -B -m diagnostics.fallback_pilot \
  --a1-report /tmp/neuraldeep-a1-once.json \
  --a1-resume-report /tmp/neuraldeep-a1-math-resume.json \
  --offline-report /tmp/harness-fallback-pilot-audit/offline.json
```

Без --live ключ не читается, HTTP transport не создаётся и intent не расходуется.

## Будущая команда — НЕ выполнять до отдельного разрешения

LLM_BASE_URL/LLM_API_KEY передаются безопасно через окружение разрешённого аккаунта.
Их значения не нужно печатать или передавать в аргументах команды.

```bash
BUDGET=900 .venv/bin/python -B -m diagnostics.fallback_pilot --live \
  --a1-report /tmp/neuraldeep-a1-once.json \
  --a1-resume-report /tmp/neuraldeep-a1-math-resume.json \
  --offline-report /tmp/harness-fallback-pilot-audit/offline.json \
  --output /tmp/neuraldeep-math-d15-pilot
```

Один результат покажет, получен ли правильный ответ через штатный fallback и на
каком шаге закончилась неуспешная попытка. Это не общая оценка качества модели.
Возврат 0 требует правильного ответа и отсутствия safety_stop. Ошибку нельзя
исправлять автоматическим повтором с другим output.
