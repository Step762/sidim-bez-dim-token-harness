## Порядок исполнения и причина

CLI: чтение offline-квитанции → fingerprint/task/budget preflight → проверка
LIVE-бюджета → mkdir нового output → создание incomplete report → чтение
конфигурации → повторный preflight/config check → durable intent → workflow → HTTP.

Сохранившиеся incomplete-файлы показывают прохождение первого preflight,
LIVE budget и создания output. Отсутствие intent при сохранности журнала
означает, что нормальный путь этого кода не дошёл до HTTP. Одна incomplete-
квитанция не доказывает отправку и сама по себе никогда не разрешает повтор.
Подтверждённый расход остаётся155.9; новой статистики провайдера нет.

**Точную исходную причину из этих данных восстановить нельзя.** Общий except
одинаково скрывал ошибку конфигурации, повторного preflight и файловую ошибку
перед intent. В частности, отсутствие/неверный endpoint или ключ полностью
совместимо с наблюдаемыми следами, но не доказано для прежнего терминала.
Сейчас дополнительно существует доказанный барьер: старый output уже занят,
поэтому тот же CLI остановится на mkdir даже при исправной конфигурации.
Окружение текущей сессии также не готово для LIVE. Это разные факты, их нельзя
выдавать за единственную историческую корневую причину.

Подтверждённый дефект диагностики — потеря стадии отказа. В search_main добавлен
allowlist-код stage (offline_receipt,task_preflight,live_budget,output_directory,
output_receipt,live_configuration,one_shot_execution,recovery), без текста
исключения, значения конфигурации или payload. Условия допуска не ослаблены.
Общая проверка Search config переиспользована до вызова one-shot runner.

Новый узкий тест воспроизводит отсутствие конфигурации на временном output:
stage=live_configuration, incomplete остаётся, intent отсутствует, сеть
запрещена. Повтор той же искусственной команды получает output_directory,
также без intent/HTTP. Остальные Search-pilot регрессии запущены вместе с ним;
окончательные результаты приведены в отчёте Q4.

## Слот и дальнейшие действия

На начало Q4 канонический слот **не занят обнаруженным intent**. Старые тесты
изолируют SEARCH_STATE во временных каталогах; предыдущая финальная проверка Q3
также зафиксировала отсутствие канонического state. Признаков случайного
занятия настоящего слота тестами нет. Новый тест не использует private-state.

Это не разрешение повторять LIVE с другим output/state. Исходный output,
offline-квитанция и все старые private-state сохраняются. После изменений Q4
fingerprint Q3 закономерно станет устаревшим; подмена хешей запрещена.

До любого следующего настоящего вызова необходимы отдельное разрешение,
подтверждение конфигурации/принадлежности аккаунта без вывода ключа, свежая
офлайн-проверка текущего runtime и явное решение о судьбе неудачной попытки.
Ни переименование output, ни удаление intent не предлагаются как обход.
После расширения локального Search следует сначала проверить, осталась ли
вообще необходимость платить за search_d15: локальный успех делает старый
пилот непригодным для измерения LLM-fallback. A2 остаётся заблокированным.
