## Внесённые изменения

Новый runtime_limits.py, включённый в явный Docker allowlist. Монотонный deadline
от начала CLI: 3540 с, отдельная операция/workflow по умолчанию 30 с. Более короткий
run задаётся --time-limit, per-operation — --operation-timeout. Сигнальный таймер
ограничивает синхронные чтение/признаки/подготовку/решатели/публикацию; asyncio.timeout
ограничивает await workflow. Собственный HTTP timeout и BudgetManager не меняются.
Отдельно ограничены синхронные prepare, разбор JSON и локальное исполнение
плана внутри fallback; сигнальный таймер никогда не остаётся активным через await.
Вечерний регрессионный тест сначала воспроизвёл задержку 0,467 с при лимите
0,04 с, затем прошёл после добавления этих границ. Подтверждённый usage при
таймауте локальной проверки остаётся учтённым, без ложной заморозки бюджета.
Локальный timeout не отправляет задачу повторно к модели. Успешные предыдущие
ответы сохраняются, незавершённая атомарная запись убирает только свой временный файл.

Планировщик сохраняет local-first, формулу ранжирования, один local и один LLM-attempt
на задачу. Режим не выбирается по числу задач. Состояния timed_out/time_exhausted
означают ограничение времени, не доказанную неразрешимость задачи.

Это Linux/main-thread контроль доверенного harness, не новая песочница. Внешний
часовой supervisor нужен для непрерываемого ядром I/O и неисправного окружения.
Недоверенный coding не включается. Решатели, gateway, формула бюджета и validator
не менялись. После изменения runtime старые live-квитанции закономерно не проходят
допуск: исторические файлы сохраняются, их хеши не подделываются. Unit-тесты истории
явно изолируют старый attested runtime от нового рабочего дерева; production-гейт
остаётся строгим.

## Воспроизведение независимой проверки

```bash
timeout 1000s .venv/bin/python -B -m diagnostics.qualification_audit --output /tmp/cycle-b-new
timeout 700s .venv/bin/python -B -m unittest discover -s tests -v
timeout 1000s docker build --no-cache --pull=false -t sidim-bez-dim:reserve-20261109-cycle-b-evening .
timeout 900s .venv/bin/python -B tests/docker_smoke.py --image sidim-bez-dim:reserve-20261109-cycle-b-evening
```

qualification_audit использует исходные 20 frozen-пар отдельно в local и mock-good,
не перезаписывая benchmark/results. Дополнительно проверяются 16 упорядоченных
сочетаний типов на простых поддержанных controls; это отдельный тест изоляции,
не улучшенная оценка покрытия. Для каждого типа берутся две разные задачи.
Ещё четыре набора проверяют API outage, неизвестный usage, timeout и недостаточный
резерв. Все HTTP здесь — mock/loopback, ключи окружения не передаются worker.

Причины пропусков выводятся из фактического planner outcome. fallback_disabled_local_mode
означает сознательный режим BUDGET=0, не дефицит конкурсной квоты. routing_or_grounding
означает ограничение текущего индекса/доказательств, а не отсутствие ответа во вселенной.
coding_disabled отделён от отсутствия грамматики/безопасной схемы плана.
