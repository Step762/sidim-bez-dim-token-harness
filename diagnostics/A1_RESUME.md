# A1: одноразовое продолжение только a1_math

Это инструменты разработки. Production-код, Docker и критерии валидаторов не
меняются. Подготовка и тесты не отправляют запросов в NeuralDeep. Приведённая
ниже live-команда требует отдельного разрешения команды.

## Зафиксированные ограничения

- Только qwen3.6-35b-a3b-noreason и исходный NeuralDeep endpoint.
- Только исходная синтетическая a1_math, max_tokens=64, один новый HTTP-запрос.
- BUDGET=600 для всей серии. Уже потрачено 14.5 за a1_ack; доступно 585.5.
- История восстанавливается через reserve/settle существующего BudgetManager,
  отдельного счётчика денежных списаний нет.
- Резерв math: 1241 / 10 + 64 = 188.1. С прежним расходом — 202.6.
  Это прогноз на основе эвристики, не доказанный удалённый потолок списания.
- Максимум два HTTP-запроса суммарно после этого продолжения. Нет retries,
  редиректов, повторного ack, запуска a1_limit или A2.
- Успех math не меняет провал старого ack: contract_observed всей серии остаётся
  false, а режим A1_resume не принимается существующим пропуском в A2.

## Проверка исторических и новых хешей

Принимается ровно рассмотренная историческая LIVE A1-квитанция. Её SHA-256:
`d119deb1bde48bc351c97bdfb916477f32730513a24a2e90c6c92dcf2bd7b50b`.

Проверяются LIVE/mode, модель, endpoint_digest, полный runtime fingerprint,
единственная подтверждённая проба ack, usage и итог бюджета. Другой JSON,
неподтверждённый расход и mock-квитанция не разрешают запуск.

Старые хеши cycle_a/trace отличаются от новой версии из-за внесённых исправлений.
Они проверяются по явно зафиксированному историческому набору, совпадающему с
diagnostics/results/offline.json и исходным LIVE-отчётом. Это узкая проверенная
миграция одной квитанции, без общего флага ignore-hashes. Неизменный selection.py
и отдельный fingerprint всех параметров синтетических проб защищают исходные
инструкции, max_tokens, модель и бюджет.

Дополнительно требуется свежая passing offline-квитанция текущей версии.
Текущий diagnostic fingerprint включает a1_resume.py. Любое непредусмотренное
расхождение останавливает запуск до HTTP. Исторические результаты не обновляются
под новые хеши.

## Журнал, который нельзя обойти новым именем отчёта

Фиксированный каталог `diagnostics/.a1-resume-state/` находится на постоянном
диске проекта. Он имеет права 0700, файлы — 0600; каталог исключён из Git.
Он не зависит от --output и имени/места копии исходной квитанции. Ключ серии —
проверенный хеш исходной квитанции, проба строго a1_math.

Перед возможным HTTP:

1. Выполняются проверки истории, новых офлайн-результатов, параметров и бюджета.
2. Открываются отдельные выходные файлы и приватные файлы захвата ответа.
3. Через O_CREAT|O_EXCL|O_NOFOLLOW создаётся неизменяемый intent-файл.
4. Его содержимое сбрасывается на диск через flush/fsync; затем fsync каталога.
5. Только после успешного завершения этих операций вызывается настоящий шлюз.

Содержимое intent не включает ключ, Authorization или prompts. Там есть хеши,
исторический расход, параметры новой пробы и отметка may_have_been_sent.
После ответа отдельный result-файл сохраняется аналогично. Исходная квитанция
не перезаписывается. Конкурирующие процессы не могут одновременно получить
одну попытку: O_EXCL допускает только одного владельца.

Наличие intent всегда запрещает повтор: даже при пустом/повреждённом файле,
ошибке fsync, отсутствии результата или смене --output. После подтверждённого
результата повтор тоже запрещён. Ложный отказ после сбоя до фактической отправки
здесь сознательно предпочтительнее дополнительного запроса с неизвестным исходом.

Журнал нельзя удалять, очищать или обходить запуском другой копии репозитория.
Гарантия относится к процессам, использующим этот общий сохранённый журнал
и файловую систему, соблюдающую fsync. При утрате журнала продолжение запрещено
до ручного выяснения состояния: серверная идемпотентность NeuralDeep неизвестна.
Отчёты /tmp можно потерять при перезагрузке; постоянный intent всё равно блокирует
повтор. CLI не предоставляет сброса или снятия блокировки.

## Офлайн-проверка перед разрешением

```bash
.venv/bin/python -B -m diagnostics.a1_resume \
  --resume-from /tmp/neuraldeep-a1-once.json \
  --offline-report /tmp/harness-a1-resume-audit/offline.json
```

Без --live это только preflight: не читает ключ, не создаёт intent и не
конструирует HTTP transport. Готовность означает прохождение локальных проверок,
а не наличие разрешения на HTTP или подтверждение принадлежности аккаунта.

## Точная будущая команда: сейчас НЕ выполнять

LLM_BASE_URL/LLM_API_KEY задаются безопасно в окружении. Их значения не печатаются.
Настроенный base URL должен точно совпасть с историческим; ключ проверяется до
отправки, но определить владельца аккаунта по строке ключа инструмент не может.

```bash
BUDGET=600 .venv/bin/python -B -m diagnostics.a1_resume --live \
  --resume-from /tmp/neuraldeep-a1-once.json \
  --offline-report /tmp/harness-a1-resume-audit/offline.json \
  --probe a1_math --capture-a1-response \
  --output /tmp/neuraldeep-a1-math-resume
```

Текст единственной инструкции — исходная искусственная задача 2+3. Захват
ограничен 2048 UTF-8 байтами message.content в приватном /tmp. Отчёт содержит
только путь и метаданные захвата, отдельные HTTP/API, JSON, schema, value,
generation и usage проверки, подтверждённую стоимость и время новой пробы.
Известный ключ и текст Authorization/Bearer в ответе приводят к его редактированию.

Возврат 0 означает успех новой math-пробы, а не всей серии A1. При неуспехе
команду нельзя автоматически повторять с другим именем output.

## Восстановление после прерывания — только чтение

```bash
.venv/bin/python -B -m diagnostics.a1_resume --recover \
  --resume-from /tmp/neuraldeep-a1-once.json \
  --output /tmp/neuraldeep-a1-math-recovered
```

Здесь никогда нет HTTP. Если приватный результат успел сохраниться, он
восстанавливается в отдельный отчёт. Если есть только intent/обрезанный result,
исход отмечается как unknown; сохраняются старые 14.5, новый резерв 188.1 и
frozen=true. Повторная отправка запрещена. Просмотр результата не снимает
блокировку. Если нет intent, recovery сообщает not_attempted и тоже не отправляет
запрос. Авторизация, квота, неизвестный usage и превышение оценки/генерации
не вызывают дополнительные запросы.

## Тесты

test_a1_resume.py проверяет исторические хеши и параметры, расход 14.5 в общем
бюджете, единственную math-пробу, повтор/копию квитанции/новый output,
конкурирующие claims, fsync файла и каталога, настоящий выход дочернего процесса
во время mock-транспорта, повреждённый результат, восстановление без HTTP,
API/usage ошибки и отсутствие утечек. Фикстура a1_ack_legacy.json содержит только
исторические метаданные, без ответа, ключей, headers и prompts.

Повторная проверка подготовки: **373/373 теста** за 162.151 с (354 прежних +
19 новых), 22/22 офлайн-сценария и git diff --check успешны. Офлайн-preflight
реальной исходной квитанции: ready=true, spent=14.5, available=585.5,
max_new_requests=1. Хеши 15 production/build-файлов и обоих исходных A1-отчётов
не изменились. Канонический intent не создан, новых NeuralDeep-запросов 0.
Сводка: `/tmp/harness-a1-resume-audit/verification.json`; полный лог: `unit.log`.
