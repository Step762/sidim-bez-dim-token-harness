## Что известно об API и что ещё неизвестно

Регламент, раздел «Модели и учёт токенов», задаёт четыре модели и стоимость
`input_tokens / 10 + output_tokens`, включая reasoning без скидки за кеш.
Разделы «Среда выполнения» и «Сдача решения» задают переменные прокси и Docker.
HTTP-схема в регламенте не определена. Из сообщения команды известен ожидаемый
NeuralDeep URL и OpenAI-compatible Chat Completions. Это исходное предположение,
а не результат проверки настоящего сервера этой версией harness.

| Область | Подтверждено исходниками и локальными тестами | Не подтверждено для NeuralDeep |
| --- | --- | --- |
| Конфигурация | LLM_BASE_URL и LLM_API_KEY читаются из окружения; Bearer; URL без credentials/query/fragment | Квота конкретного ключа, права и совпадение с конкурсным прокси |
| Endpoint | `/v1` превращается в `/v1/chat/completions`; полный endpoint повторно не дописывается | Доступность реального endpoint сейчас |
| Модели | MODELS содержит qwen3.8-27b, qwen3.8-27b-noreason, qwen3.6-35b-a3b, qwen3.6-35b-a3b-noreason | Наличие каждой модели, фактическая маршрутизация и возможные aliases |
| Запрос | POST; system и user; content обоих сообщений — строки; user содержит JSON контекста; max_tokens и stream=false | Принятие max_tokens/stream и точная семантика их ограничений |
| Дополнительные параметры | temperature, response_format, tools, seed и специфические thinking-параметры не добавляются | Их поддержка не предполагается по другим провайдерам |
| Ответ | Один choices, message.role=assistant, непустой строковый content, finish_reason=stop | Всегда ли провайдер возвращает именно эту форму |
| Content | Массив частей, null, tool_calls и пустой текст отклоняются | Нужен ли адаптер content parts; сейчас такого основания нет |
| JSON | Внешний API JSON и внутренний JSON-план разбираются отдельно; дубли ключей/нечисловые константы запрещены | Соблюдение моделью JSON-инструкции без response_format |
| Finish reason | stop допускает обработку; length отклоняется даже при внешне полном JSON; достоверный usage всё равно списывается | Реальные finish_reason и наличие usage при length |
| Usage | prompt_tokens и completion_tokens обязательны, целые неотрицательные; total_tokens необязателен, но при наличии согласован | Полнота и достоверность реальной статистики, скрытая серверная надбавка |
| Reasoning | Поддержаны два известных коду расположения счётчика; включённая/отдельная схема задаётся только доверенной AccountingPolicy | Какая схема у NeuralDeep, учитывает ли max_tokens всю генерацию |
| Неизвестные поля | Игнорируются; их отсутствие/наличие не доказывает семантику счётчиков | Нельзя выводить «reasoning бесплатны/отсутствуют» из отсутствующего поля |
| Ошибки | HTTP 400/401/429/500/503: без retries; неизвестный расход удерживает резерв и замораживает общий менеджер; 401/403/429 также блокируют шлюз | Тексты ошибок, rate limit, политика отмены и тарификация ошибок сервера |
| Timeout/partial body | Локальный timeout; неполученный usage не объявляется нулевым, partial response не исполняется | Останавливается ли генерация на сервере после локального timeout |
| Размеры | Контекст до 18000 символов; HTTP-ответ до 128 КиБ; max_tokens в коде 1–4096 | Серверные лимиты и реальная токенизация |

Список разрешённых моделей и доступность вызова — разные условия. Без
проверенного AccountingPolicy reasoning-варианты блокируются до HTTP. Для A1
выбран только `qwen3.6-35b-a3b-noreason`. Неожиданный ненулевой reasoning usage
делает расход неопределённым; A1 отдельно останавливается при явно возвращённом
reasoning_content. Это наблюдения и консервативные проверки, не доказательство
отсутствия скрытых рассуждений во всех будущих ответах.

Поле model в ответе необязательно для нашего шлюза. A1 сверяет его, если оно
предоставлено; несовпадающий alias требует разбора, а не молчаливого предположения
о модели. Отсутствующий tag не удостоверяет реальную модель сервера.

## Бюджет

Используется исходный BudgetManager. До HTTP резервируется эвристика UTF-8
байтов сериализованных сообщений плюс 1024, делённая на 10, плюс max_tokens.
**Это не точный токенизатор и не доказанный верхний предел входа.** После
достоверного usage резерв заменяется расходом, кеш не даёт скидки. Идемпотентное
согласование не списывает повторно. Неизвестный расход сохраняет резерв и
останавливает новые модельные вызовы всего запуска, сохраняя локальные ответы.

При подтверждённой included-схеме reasoning не прибавляется к completion ещё
раз. При подтверждённой separate-схеме прибавляется ровно один раз. Без контракта
ненулевой reasoning запрещает дальнейшие вызовы. Диагностика различает сырые
completion_tokens и accounted_output_tokens в событиях учёта.

Если фактические токены превысили резервную оценку, весь известный расход
учитывается и менеджер замораживается. Это обнаружение после факта, а не
физическое ограничение сервера. Неизвестные входные надбавки и неподтверждённое
соблюдение max_tokens не позволяют обещать абсолютный потолок удалённого расхода.

Никакого нового счётчика списаний нет: отчёт читает snapshot менеджера.
transport_attempts считает попытки транспорта, не является вторым бюджетом.
Сохраняется исходный callback openJiuwen, запрещающий внеучётные SDK-запросы.
Диагностика не добавляет модельных запросов. BUDGET=0/нехватка полного резерва
не отправляют HTTP; неизвестный usage и ошибки не вызывают retries.

## Состав инструментов

- selection.py: фиксированные 12 development-задач, прогноз резервов и A1-пробы.
- trace.py: временные наблюдатели настоящих Workflow.invoke, prepare, strict_json,
  validate, исполнительных функций, BudgetManager и атомарного save_answer.
- cycle_a.py: офлайн-сценарии, независимая оценка, вывод JSON/Markdown и отдельно
  защищённые команды будущих A1/A2. Ключи читаются только в ветке --live.
- results/plan.json и plan.md: выбранные задачи, эталоны оценщика, причины выбора,
  локальные результаты и оценки расхода. Эталоны не передаются модели.
- results/offline.json и offline.md: воспроизводимые эксперименты без NeuralDeep.

Рабочая задача содержит исходные четыре поля benchmark. Модель получает только
обычный контекст production prepare. Для math это инструкция; для search —
необходимые поля выбранных связанных записей; для CSV — инструкция, имя,
заголовки и число строк, без всей таблицы. Публичные синтетические исходные факты
не являются скрытыми grading-эталонами. Coding и holdout в live-подборку не входят.

Трасса: task → local_attempt → llm_eligibility → budget_reservation →
model_response → parsed_plan → semantic_validation → execution → answer.txt.
Для локального успеха модельные стадии не нужны. У search проверка и извлечение
факта объединены внутри исходной closure; событие явно отмечает эту общую
границу, не изображая отсутствующий отдельный исполнитель.

При полученных HTTP headers запрос подтверждён отправленным. Без headers после
connect/timeout точная отправка может быть неизвестна: request_sent=null, а не
ложное обещание false. У mock-обработчика есть отдельное подтверждение приёма.
Это важно для неопределённого расхода и отказа от автоматического повтора.

По умолчанию сохраняются только allowlisted metadata, размеры, коды и счётчики. Не сохраняются
Authorization, API-ключ, тексты provider errors, prompts, полные документы,
полные ответы и планы. Внутренний разбор использует план в памяти и записывает
результат независимой проверки. Дополнительно известный ключ редактируется из
строк metadata. Параметр --no-trace выключает подробные события, сохраняя итоговые
категории и бюджет. Production вообще не импортирует эти инструменты.

Единственное опциональное исключение: `--capture-a1-response` разрешён только
в режиме A1 для трёх фиксированных искусственных инструкций. Он сохраняет
только message.content в автоматически созданный приватный каталог `/tmp`
(0700), файлы имеют права 0600. Текст ограничен 2048 UTF-8 байтами; отмечены
обрезание и редактирование. При обнаружении известного ключа либо текста
Authorization/Bearer весь ответ заменяется отметкой. Headers, envelope,
reasoning_content и prompts не сохраняются. Дескрипторы открываются до HTTP,
запись идёт через них; отчёт содержит путь, а не текст. Отказ записи останавливает
запуск. Файлы предназначены для локального просмотра, не для Git или публикации.

Hooks временные и предназначены для последовательной разработки в одном
процессе. Они не меняют выбор задач и не подменяют workflow/ledger. Запись
отчётов осуществляется только в явный --output; оба файла открываются до
возможного HTTP, существующие отчёты не перезаписываются. На read-only пути
команда откажется до чтения ключа и отправки запросов. В обычном конкурсном
запуске никакие файлы диагностики не создаются.

## Категории потерь

| Категория | Доказательство |
| --- | --- |
| routing | Задача не дошла до модели: локальный evidence gate или подготовка контекста отказала |
| model_meaning | Получен разбираемый план; независимая проверка установила иной смысл/явный отказ модели |
| response_format | Не JSON, неверная схема/тип content, обрезанная генерация; это не доказательство неверного понимания |
| validator_rejection | Независимо доказанный эквивалентный план не принят текущим валидатором |
| execution | Проверенный план принят, затем исполнитель завершился ошибкой/дал неверный результат |
| answer_publication | Ошибка записи или правильный кандидат отличается от записанного значения |
| api_or_budget | HTTP, timeout, partial body, unknown usage, reasoning-контракт, резерв или лимит запросов |

Неоднозначные случаи имеют validation_unassessed/answer_incorrect: инструмент
не выдумывает виноватый компонент. Обоснованный отказ от повреждённых данных
учитывается отдельно, без объявления ошибки модели.

Независимый oracle планов ограничен тремя заранее проверенными development
планами. В математике сравниваются упорядоченные аффинные преобразования, а не
только конечный ответ. Для math_d15 sub(8) и add(-8) задают одинаковую карту
x → x-8, затем обе умножаются на 4. Такой план с корректными строковыми полями
и цитатами production отклоняет. Это подтверждённый узкий случай валидатора,
не основание автоматически принимать любые алгебраические перестройки.
Непроверенная цитата или неизвестная семантика получает not_assessed.

В execution_error/save_error/format_error применяется явная контролируемая
инъекция сбоя только к math_d15. Это тест наблюдателя, не найденная ошибка
исполнителя и не измерение способности модели. Классификация проверяется также
на HTTP 400/401/429/500/503, timeout, полном/частичном отсутствии usage,
недостаточном/нулевом бюджете, двух уровнях обрезанного JSON, частично полученном
HTTP body, content parts и length. Все эти случаи используют локальные моки.

## Конкретный будущий эксперимент — пока НЕ выполнять

План ниже описывает первоначальный полный A1, а не продолжение выполненной
пробы. Один запрос уже потрачен. Не запускайте эту команду заново под видом
продолжения: текущий CLI всегда начинает с a1_ack. Осталось не более двух
запросов исходного лимита; новый a1_resume разрешает только один из них, a1_math.
Исторические
квитанции не перезаписываются, новый код делает прежнюю offline-квитанцию устаревшей.

URL: ожидается `https://api.neuraldeep.ru/v1/chat/completions`, фактическая
конфигурация берётся исключительно из LLM_BASE_URL/LLM_API_KEY. Модель:
`qwen3.6-35b-a3b-noreason`. Не используются reasoning-модели и новые параметры.

**A1: максимум 3 запроса, BUDGET=600.** Два маленьких protocol/JSON-запроса
(ack и 2+3) и один намеренно длинный ответ при max_tokens=32 для проверки length.
Лимиты ответа: 32, 64, 32; всего запрошено не более 128 выходных токенов при
соблюдении сервером max_tokens. Эвристики входа: 1170, 1241, 1240. Оценочные
резервы: 149 + 188.1 + 156 = **493.1** конкурсной единицы. Остаток до 600 — запас,
не разрешение на четвёртый запрос. При неожиданном контракте/unknown расходе
дальнейшие пробы прекращаются; автоматических повторов нет.

A1 проверяет только малую выборку. Даже успешные три пробы не доказывают общий
жёсткий серверный cap, отсутствие скрытых reasoning или полную доступность всех
четырёх моделей. Квитанция не является аттестацией модели провайдера.

**A2: 12 задач, естественно не более 3 HTTP-запросов, BUDGET=2500.** Только после
успешного настоящего A1 и нового отдельного разрешения. Сейчас к LLM проходят
math_d15, search_d15 и data_analysis_d14. При max_tokens=512 на вызов их резервы
700 + 694.3 + 720.8 = **2115.1**. У остальных четырёх локальный успех, у пяти —
отказ до модели. Не нужно обходить эти отказы и выдавать дополнительные
shadow-запросы за штатную работу harness. Способность модели на отсечённых
формулировках этим естественным прогоном не измеряется; для неё нужен отдельный
план и разрешение после анализа A1/A2.

Приведённые суммы — план консервативного резервирования, **не доказанная верхняя
граница удалённого счёта**: входная оценка и серверный max_tokens пока не
подтверждены. Если сервер нарушит ожидания, менеджер зафиксирует известный
перерасход и остановит новые вызовы после первого наблюдения. Локальный timeout
также не гарантирует остановку генерации на сервере.

Используется квота аккаунта, которому принадлежит переданный LLM_API_KEY.
Остаток, тариф/денежная цена и принадлежность ключа тестовому или конкурсному
аккаунту не проверялись. BUDGET — наш лимит одного запуска в единицах регламента,
а не баланс NeuralDeep. У конкурсного прокси могут быть другие URL, ограничения,
модели, квота и детали usage. Запросов баланса/списка моделей здесь нет.

После отдельного разрешения A1 (ключ задаётся безопасно вне исходников):

```bash
# НЕ выполнять до разрешения; LLM_BASE_URL и LLM_API_KEY уже должны быть в env.
BUDGET=600 .venv/bin/python -B -m diagnostics.cycle_a --mode A1 --live \
  --offline-report diagnostics/results/offline.json --output /tmp/neuraldeep-a1-once
```

Для будущего заново согласованного полного A1 можно отдельно включить
`--capture-a1-response`. `--continue-on-protocol-error` — ещё один явный флаг:
продолжение только после JSON/schema/value ошибки, когда API/usage/границы
проверены. Он не повторяет пробу, не увеличивает лимит трёх запросов, не отменяет
неуспех и не открывает A2. Любой сбой API, unknown usage, reasoning, превышение
оценки или лимита генерации останавливает запуск независимо от этого флага.
Это политика сбора диагностической информации внутри вновь разрешённого набора,
а не разрешение потратить ещё три запроса после исторического первого.

И отдельно после успешного A1 и разрешения A2:

```bash
BUDGET=2500 .venv/bin/python -B -m diagnostics.cycle_a --mode A2 --live \
  --offline-report diagnostics/results/offline.json \
  --a1-report /tmp/neuraldeep-a1-once.json --output /tmp/neuraldeep-a2-once
```

В отсутствие --live команды A1/A2 откажут до чтения ключа. Нельзя использовать
mock-A1 как разрешающую квитанцию для A2. Квитанции привязаны к runtime,
диагностическому коду, модели и endpoint. Отчёт с interrupted/incomplete не
разрешает A2; запросы при прерывании могли быть отправлены. Не перезапускайте
live автоматически, не меняйте путь ради повтора без оценки уже потраченной квоты.

Для live нужен явный BUDGET не меньше утверждённого лимита фазы. При нуле,
невалидном или меньшем значении выполнение откажет до чтения ключа; меньший
пользовательский лимит молча не увеличивается. Больший BUDGET ограничивается
600/2500 в менеджере конкретного эксперимента. Офлайн-сценарии могут задавать
свои тестовые лимиты, поскольку используют только моки.

После A1 решаем: совпадает ли HTTP/usage-контракт, нужна ли минимальная адаптация,
достаточен ли вывод о max_tokens для ограниченного A2 и допустим ли сам A2.
После A2 выбираем изменения маршрутизации, промпта, валидатора или исполнителя
по фактическим причинам потерь, с отдельными тестами. Цикл B автоматически
не начинается.
