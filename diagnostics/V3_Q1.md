## Запуск без настоящих моделей

Из корня полного checkout с установленными requirements:

```bash
# Только полностью вымышленные сценарии; HTTP не нужен.
.venv/bin/python -B -m diagnostics.token_economics --output /tmp/q1-synthetic-new
# Повтор на сохранённой tape без HTTP и пересбора benchmark.
.venv/bin/python -B -m diagnostics.token_economics --replay diagnostics/results/v3_q1/cheap.jsonl --output /tmp/q1-replay-new
# Настоящий workflow openJiuwen и контролируемый localhost mock, только development.
.venv/bin/python -B -m diagnostics.token_economics --collect-development --output /tmp/q1-development-new
# Независимая frozen-оценка, без подбора параметров/правил по holdout.
.venv/bin/python -B -m diagnostics.token_economics --collect-frozen --output /tmp/q1-evaluation-new
# Неподвижные20 квалификационных пар и аварийные контроли.
.venv/bin/python -B -m diagnostics.qualification_audit --output /tmp/q1-pairs-new
# Отдельные новые синтетические пары — не замена фиксированным20.
.venv/bin/python -B -m diagnostics.q1_alias_probe --output /tmp/q1-alias-new.json
```

Выбирайте новые пути: каталог/файлы не перезаписываются. Здесь нет --live, адреса
NeuralDeep или чтения настоящих ключей. Коллектор допускает только интерфейс
benchmark с локальным mock-сервером. Подготовленные prompts/ответы и документы
не экспортируются. Исторические настоящие usage доступны только как ранее
согласованные публичные сводки трёх запросов; их CLI не воспроизводит.

## JSONL schema_version=1

Одна строка — одна задача и наблюдения локальной/платной фаз. Это не диалог модели.

| Поля | Смысл |
| --- | --- |
| task_id,task_type,reward | входная идентификация и награда; reward не оценка сложности |
| trace_source,scope,model | local/mock/synthetic/real, development/holdout/гипотеза, настроенная модель |
| route,blocker | фактическая ветка для наблюдений; потенциальная для synthetic tape |
| complexity,native_form | признаки без grading-ответа |
| local_validated,local_correct,local_seconds | принят ли локальный результат, прошёл ли оценщик, время workflow-фазы |
| local_terminal,eligible | наблюдённый барьер или допустимость fallback после локальной фазы |
| llm_validated,llm_correct,llm_seconds | принял ли план валидатор, независимый результат, время фазы |
| estimated_input,max_tokens,estimated_cost,estimated_success | оценки до решения; их источник uncalibrated_engineering_prior |
| input_tokens,output_tokens,reasoning_tokens | подтверждённый вход и уже учтённый полный выход; reasoning отдельно, если известен |
| output_token_semantics,usage_known,cost,calls | контракт учёта, известен ли расход, полная стоимость, число запросов |
| refusal,time_scope | категория отказа и границы измеренного времени |

`output_tokens` здесь — **accounted total including reasoning**, не обещание
равенства сырым completion_tokens каждого провайдера. Вход/10+этот выход даёт
стоимость; reasoning повторно не прибавляется. None означает отсутствие наблюдения,
не ноль. Для настоящих сводок доступно меньше полей: время первой серии не
восстанавливается и не выдумывается. Строки протокольных A1-проб не используются
для оценки качества решения задач.

Стоимость/прогноз хранятся точной десятичной или рациональной строкой:
`"29/2"` означает14.5конкурсных единиц. В BudgetManager используются целые десятые.
Для локальных/blocked строк без LLM стоимость0. Булевы correct отражают наличие
правильного ответа данной фазы; False при невыбранной фазе не является wrong.
Wrong учитывается только для опубликованного/принятого неправильного результата.

У synthetic tape нет настоящей модельной трассы: это полностью заданная гипотеза.
Заданы потенциальная доступность локального решения, результат проверяемого
предложения, его длина и длительность. Реально выбранные попытки и причины
остановки определяет replay. Его время синтетическое либо воспроизведено по
workflow-фазам; startup, scheduler preparation и часть I/O отдельно не моделируются.
Это не замена общего deadline production и внешнего supervisor.

## Политики и ограничения replay

- production: настоящий Planner.next/estimate/finish для платной фазы, текущие priors
  и онлайн-наблюдения собственного BudgetManager;
- reward_first: награда первой среди допустимых кандидатов;
- cost_first: **прогнозная**, а не фактическая стоимость первой;
- expected_reward: reward×фиксированный prior / фиксированный прогноз стоимости;
- local_first: простейший стабильный порядок ID, затем один допустимый fallback.

Все политики сохраняют локальную фазу до платной, один запрос на задачу, полный
резерв, общий бюджет, deadline и выключенный Coding. Actual cost/correctness/
фактическая длительность никогда не выбирают первую задачу. Результаты становятся
известны после симулированного выполнения; production policy использует только
свои подтверждённые наблюдения. Трассы не обучают новый предиктор.

Replay использует реальные Planner и BudgetManager, но подставляет наблюдённые
features и результаты локальных решателей. Это **симуляция**, а не повтор SDK или
HTTP. При BUDGET100000 её порядок, correct/wrong, reward, calls и spent дополнительно
сверены с настоящим mock-workflow; несовпадение останавливает сравнение.
Симулятор не удостоверяет API-контракт модели, физическое соблюдение max_tokens
сервером или прогноз реального времени. Его входные выходные счётчики уже должны
быть согласованы коллектором/доверенной гипотезой.

Unknown usage сохраняет резерв и блокирует дальнейшие платные попытки. Известное
превышение оценки видно отдельно: cost_known=true при frozen=true. Истечение
времени до публикации не создаёт симулированный ответ, прежние ответы сохраняются.
Coding блокируется независимо от флагов корректности в поданной трассе.

`qualification` внутри одиночного replay с несколькими парами означает покрытие
этих пар **внутри одного общего запуска**. Это не квалификация организаторов.
Для настоящих фиксированных20 применяется compare_fixed_pairs: каждый запуск
содержит только две задачи, собственный полный бюджет и свой deadline. В CSV
поле isolated_fixed_pair_fraction относится исключительно к этому испытанию.
Synthetic и development пары не объявляются полным квалификационным набором.

## Сохранённые результаты и повторение на тех же данных

[results/v3_q1](results/v3_q1) содержит development и синтетические JSONL,
публичные real_summaries, агрегаты, ошибки прогнозов и CSV пяти политик на четырёх
бюджетах. Индивидуальная holdout tape не экспортируется; её агрегаты получены
оценщиком автоматически. Конкретные holdout-ответы для анализа не открывались.
SHA256 в manifest.json фиксируют входы, исследовательский код и runtime.

Повтор вычислений без HTTP, используя сохранённый JSONL:

```bash
.venv/bin/python -B - <<'PY'
from diagnostics.token_economics import read_jsonl, compare
rows = read_jsonl('diagnostics/results/v3_q1/cheap.jsonl')
for result in compare(rows):
    print(result['budget'], result['policy'], result['correct'], result['reward'], result['spent'])
PY
```

Изменение Planner между опытами меняет production replay: фиксируйте новый hash
и сохраняйте отдельный результат. Не смешивайте результат replay с измерением
нового вызова Qwen. Полный WSL/Docker требует локальных официальных примеров
codex-local; они не публикуются в Git. Целевые replay-тесты используют свои данные.
