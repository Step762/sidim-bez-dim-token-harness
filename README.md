# sidim-bez-dim-token-harness

Агент команды «Сидим без Дим» для Huawei openJiuwen Challenge 2026.
Итоговый код находится в `main`. Python и настоящий workflow openJiuwen
соединяют локальные решатели Math, Search, Data Analysis и статический Coding.
После локального отказа возможен LLM-fallback с проверкой плана и общим бюджетом.

## Сборка

Команды выполняются из корня клонированного репозитория. Нужны Docker Engine
и доступ к Docker Hub/PyPI **во время сборки**. При исполнении ничего не скачивается.

```bash
timeout --kill-after=10s 1000s docker build --no-cache --progress=plain -t sidim-bez-dim:submission .
```

База закреплена: Python 3.12.12 slim-bookworm с SHA256 в Dockerfile.
Все 169 зависимостей закреплены в requirements.txt, openJiuwen — 0.1.20.post1.
Образ CPU-only, без весов нейросетей. `.dockerignore` разрешает только21 build input;
COPY перечислены явно. Ключи, Git, .venv, локальные материалы, тесты, benchmark
и приватные состояния в образ не попадают. Три модуля статического Coding
из diagnostics входят в образ как необходимые зависимости.

## Задания и ответы

Передайте **абсолютный путь к свежим рабочим копиям** каталога задач:

```bash
export TASKS=/absolute/path/to/task-copies
```

Структура входа и результата:

```text
tasks/
  any_task_id/
    task.json                 # task_type, instruction, reward; task_id необязателен
    workspace/                # CSV, kb/*.md или Python-файлы конкретной задачи
    answer.txt                # агент создаёт после успешного решения
```

Поля expected/check не нужны и не используются для решения. У каждой задачи
изолированный workspace. Ответ сохраняется атомарно рядом с task.json,
с переводом строки и правами0644, сразу после решения. Для Coding также
сохраняется исправленный исходник; файлы тестов не изменяются. Неудачная
обработка свежей задачи не создаёт answer.txt. OUT агенту не нужен.

Каталоги задач должны разрешать запись UID контейнера. Образ запускается
как UID0; при `--cap-drop ALL` он не обходит права владельца host-каталога.
Организаторам необходимо обеспечить writable mount. Для собственного запуска
можно добавить `--user "$(id -u):$(id -g)"`, если эти UID/GID владеют заданиями.
Не изменяйте права оригинальных материалов ради проверки: используйте копии.

## Проверенный офлайн-запуск

Без API-ключа, без OUT, без внешней сети:

```bash
timeout --kill-after=10s 1h docker run --rm --pull=never --network none \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp -e BUDGET=0 \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 8 --memory 16g --pids-limit 512 \
  --mount type=bind,source="$TASKS",target=/data/tasks \
  --workdir /app --entrypoint python \
  sidim-bez-dim:submission /app/run_agent.py --tasks-dir /data/tasks --disable-llm
```

Штатный ENTRYPOINT — python; CMD — `/app/run_agent.py --tasks-dir /data/tasks`.
Для проверки ENTRYPOINT/CMD без дополнительных аргументов:

```bash
timeout --kill-after=10s 1h docker run --rm --pull=never --network none \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 8 --memory 16g --pids-limit 512 \
  --mount type=bind,source="$TASKS",target=/data/tasks \
  --workdir /app sidim-bez-dim:submission
```

Второй вариант не передаёт BUDGET и ключ: доступны только локальные решатели.
Код завершения агента:0 — задачи обработаны, включая безопасные отказы;
1 — хотя бы одна задача завершилась ошибкой;2 — ошибка аргументов/конфигурации.
Внешний timeout может вернуть124. Пропуск задачи сам по себе не является ошибкой.

## Конкурсный запуск и LLM

Ниже вариант команды организаторов с явно переданным BUDGET. Сеть hack-net,
значение бюджета, адрес и ключ Proxy предоставляет организатор. Не используйте
этот блок для проверки без отдельного разрешения на реальные LLM-вызовы.

```bash
: "${TASKS:?set absolute tasks path}" "${BUDGET:?set assigned budget}"
: "${LLM_BASE_URL:?set organizer proxy}" "${LLM_API_KEY:?set organizer key}"
timeout -k 1000s 1h docker run --rm \
  --network hack-net -e BUDGET -e LLM_BASE_URL -e LLM_API_KEY \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g -e HOME=/tmp \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 8 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python \
  sidim-bez-dim:submission /app/run_agent.py --tasks-dir /data/tasks
```

В локальном регламенте пример Docker-команды не содержит `-e BUDGET`, а команда
сборки напечатана без обязательного контекста `.`. Здесь контекст указан;
передачу BUDGET следует подтвердить с организатором. Не подставляем100000
автоматически. Упомянутый в старом тексте OUT в фактической Docker-команде
не используется и не требуется для answer.txt. TASKS — переменная host-оболочки,
внутри контейнера каталог задаётся аргументом `--tasks-dir /data/tasks`.

| Параметр | Поведение |
|---|---|
| BUDGET | Неотрицательное целое, общий лимит выходных эквивалентов. Нет переменной или0 — LLM выключен |
| LLM_BASE_URL | Полный base URL разрешённого организатором Proxy; gateway добавляет /chat/completions, если нужно |
| LLM_API_KEY | Только environment при запуске; не помещать в Dockerfile, Git, командную строку или отчёты |
| OUT | Не используется |
| --disable-llm | Запрещает LLM даже при полном окружении |
| --enable-llm | Требует явного бюджета и корректной конфигурации |
| --llm-model | По умолчанию qwen3.6-35b-a3b-noreason |
| --llm-timeout / --llm-max-tokens | По умолчанию20s /1024 |

LLM автоматически включается только при полной конфигурации BUDGET+URL+KEY
и положительном бюджете. Учитывается `input_tokens / 10 + accounted_output`,
включая reasoning; кеш не уменьшает input. BudgetManager резервирует средства
перед вызовом. Неизвестный расход сохраняет резерв и блокирует следующие
LLM-вызовы; ошибка не считается бесплатной. Gateway не делает автоматических
повторов и обрабатывает запросы последовательно. Установленная квота Proxy
и фактический wire-контракт не подтверждаются локальными mock-тестами.

До вызова вход оценивается как размер JSON-сообщений в UTF-8 байтах плюс1024
на оформление; резерв — эта оценка/10 плюс max_tokens. Это эвристика,
не tokenizer и не гарантия скрытых накладных расходов провайдера. Планировщик
сначала выполняет локальные попытки, затем допускает не более одной LLM-попытки
на задачу с проверкой бюджета. Отсутствие файлов/фактов, неоднозначность и
провал проверки плана дают отказ. Неподдерживаемость не доказывает математическую
невыполнимость: при неопределённости агент пропускает задачу.

Регламент разрешает qwen3.8-27b, qwen3.8-27b-noreason, qwen3.6-35b-a3b,
qwen3.6-35b-a3b-noreason. Reasoning-варианты без отдельно подтверждённого полного
лимита генерации и семантики usage отклоняются gateway; выбирайте проверенную
конфигурацию. Совместимость настоящего конкурсного Proxy здесь не заявляется.
Диагностический NeuralDeep LIVE-пилот не входит в образ и остаётся заблокирован
до валидного approval; текущий код не создаёт такое разрешение автоматически.

## Локальные возможности и ограничения

- Math: поддерживаемые арифметические формулировки, проценты, точные вычисления
  и проверка порядка операций/единиц. Не универсальная математическая система.
- Search: извлечение фактов и подтверждённые цепочки по Markdown из workspace/kb;
  противоречия и недостаточные доказательства приводят к отказу.
- Data Analysis: локальный CSV-парсер, поддерживаемые агрегаты, фильтры и выборки;
  вычисления выполняются стандартной библиотекой без отправки таблиц модели.
- Coding: по умолчанию ограниченный AST-маршрут без import/eval/exec исходников
  задачи и без ручных контрактов. Сам выбирает единственную подтверждённую
  правку по литеральным unittest-проверкам и публикует исправление и DONE.
  Поддержка частичная; видимые проверки не заменяют скрытые тесты организатора.

`--disable-static-coding` отключает Coding. `--static-coding` оставлен как явный
выбор того же статического маршрута. `--trusted-code` вместо него запускает
тесты только в явно доверенных копиях; флаг не является песочницей и не должен
использоваться для недоверенных финальных задач. Эти три режима взаимоисключающие.
При повторном статическом Coding-прогоне старый answer.txt сбрасывается перед
перепроверкой; уже исправленный исходник сохраняется и проверяется заново.

Search Graph, MathIR и Semantic Compiler не включаются автоматически.
Данные документов и исходников рассматриваются как данные, а не инструкции
по изменению поведения агента. Символические ссылки и специальные файлы
отклоняются; размеры входов ограничены. Произвольный недоверенный Python
не исполняется. Наличие двух задач не включает особый режим квалификации.

## Ресурсы и время

Контейнер проверен с read-only root, tmpfs2GiB,8CPU,16GiB RAM,512 процессами,
без capabilities и с no-new-privileges. Также проверялось ограничение4CPU:
в таблице локального регламента указаны4 ядра, в его Docker-команде —8;
прямое уточнение организатора, переданное команде, подтверждает8 логических CPU.
Образ должен быть меньше4GB, репозиторий без .git — меньше100MB.

Общий монотонный дедлайн агента3540s, синхронная операция по умолчанию30s,
сетевой запрос20s. `--time-limit` можно уменьшить, но не поднять выше3540s;
`--operation-timeout` задаёт лимит операции. Уже опубликованные ответы
сохраняются при последующем отказе. Официальный внешний часовой timeout
остаётся обязательным; процесс не рассчитывает на остановку Proxy для бюджета.
