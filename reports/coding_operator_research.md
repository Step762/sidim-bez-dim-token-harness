# Статическая проверка арифметических исправлений Coding

Эксперимент для C5 (`ae9351c`). Генератор C3 предлагает правку, а отдельный
проверяющий модуль разбирает исходник и кандидата заново. Он проверяет, что
имя функции, параметры и порядок операндов совпадают, а единственное изменение
заменяет ошибочный оператор на операцию из переданного контракта.

## Граница проверки

- Поддерживается один обычный `def f(a, b)` с телом `return a OP b`. Аргументы
  должны быть точными встроенными `int`, для которых `+`, `-` и `*` реализуют
  соответствующие операции при наличии ресурсов. Деление допускается на стороне
  исходного дефекта. Другие типы и гарантии по ресурсам вызова вне домена.
- Контракт задаёт оператор диагностики. Имена и тесты задач не определяют
  контракт. Код и тесты задач не импортируются и не запускаются.
- Читается один обычный UTF-8-файл внутри workspace через `safe_files`.
  Ограничения составляют 64 КиБ, 256 узлов AST и 2 секунды на операцию.
  Результат — координаты одного токена (строка и столбец с единицы, столбец
  в символах) и его замена. Диагностика ничего не записывает в workspace.

## Development

Для прогона вручную заданы гипотезы `join(a, b) = a + b` и
`product(a, b) = a * b` на указанном домене. Это контрольные контракты
эксперимента. Их полнота для конкурсных задач независимо не подтверждена.

| Маршрут | Correct | Wrong | Skipped | Unverified | Баллы |
| --- | ---: | ---: | ---: | ---: | ---: |
| Безопасный C5, исходная метрика development Coding | 0 | 0 | 16 | 0 | 0 |
| Изолированная диагностика с двумя гипотезами | 0 | 0 | 14 | 2 | 0 |

На `d01` доказана замена `-` на `+` при заданной гипотезе (reward 3),
на `d02` — `/` на `*` (reward 13). Остальные 14 задач в этом эксперименте
не получили контракта. Ни один результат не объявлен конкурсным успехом.
Все разрешённые development-файлы остались побайтово прежними.
В отдельном прогоне 16 задач в WSL проверка заняла 59 мс, пиковый RSS
процесса Python составил 19 940 КиБ. Это один замер, включая чтение файлов
и запуск анализа, без старта интерпретатора.

## Воспроизведение в Linux или WSL

```bash
python3 -B -m unittest discover -s tests -p test_coding_research.py -v
python3 -B -m unittest discover -s tests -p test_static_coding.py -v
python3 -B -m diagnostics.coding_research --experimental-static-coding \
  --task-dir benchmark/dataset/tasks/coding_d02 --source engine.py \
  --function product --contract multiply
```

Для повторения прогона development из корня репозитория:

```python
from collections import Counter
from pathlib import Path

from diagnostics.coding_research import review_task

contracts = {1: ("join", "add"), 2: ("product", "multiply")}
statuses = Counter()
for number in range(1, 17):
    task = Path(f"benchmark/dataset/tasks/coding_d{number:02}")
    function, contract = contracts.get(number, (None, None))
    result = review_task(task, Path("engine.py"), function=function, contract=contract)
    statuses[result["status"]] += 1
    assert result["contest_solution_confirmed"] is False
    assert not (task / "answer.txt").exists()
print(dict(statuses))
```

В WSL прошли 9 тестов нового модуля и 15 тестов C3. В частности, проверяющий
отклонил кандидат с неверной операцией даже при положительном флаге генератора.
Полный регрессионный набор и Docker smoke в этом цикле не запускались.

## Условия интеграции

Интегратору нужно отдельно подтвердить источник и полноту контрактов,
проверить замороженный модуль на свежих приёмочных примерах и повторить
регрессии. Поле `independently_verified_under_contract` подтверждает только
свойство кандидата на заданном домене. Публикация `DONE` требует независимой
приёмки полного контракта задачи и согласованного production-маршрута.
