## Реализация и семантика

Из production-кода в C1 изменён только `data_solver.py`. Существующий
построчный проход накапливает прежние `(count, total, extreme)` по ключам
групп; скалярный маршрут использует тот же расчёт. Числа считаются через
`Fraction`, без eval/exec, SQL от модели и недоверенного Python.

Поддержанная полная формулировка:

```text
Using ledger.csv, return a JSON object mapping each team to its total amount.
Using ledger.csv, return a JSON object mapping each team to its average amount where day >= 2.
Using ledger.csv, return a JSON object mapping each team to its row count.
```

- Агрегаты: total/sum, count, min/minimum, max/maximum, avg/average;
  перед целевым столбцом допустимо `of`. Фильтры — прежние AND-сравнения и
  явно включённые диапазоны. Имена файлов, столбцов и значения не фиксированы.
- Ключи JSON — точные CSV-строки. `01`, `1`, `1.0`, `blue` и ` blue `
  различаются. Числовой тип ключа по содержимому не угадывается.
  Пустой/пробельный ключ вызывает отказ вместо выдумывания NULL-группы.
- Значения JSON — числа, не строки. Целые и конечные десятичные дроби
  сериализуются точно, включая числа вне точности float. Для среднего 1/3
  без заданного округления ответ не создаётся.
- `row count` считает строки независимо от незадействованных полей.
  `count amount` считает непустые значения столбца; пустое значение приводит
  к отказу, как в прежнем COUNT. Смешанные непустые строки допустимы для COUNT,
  но не для числовых SUM/AVG/MIN/MAX.
- Пустой CSV с корректным header и пустая отфильтрованная выборка дают `{}`:
  нет наблюдаемых групп. Не создаются отсутствующие ключи с нулями.
  Пустые строки файла допустимы; повреждённые строки и задействованные числа,
  в том числе вне фильтра, приводят к отказу от всего ответа.
- Порядок ключей детерминирован. Это сериализация JSON-объекта, не поддержка
  пользовательской сортировки строк. Не более 10000 наблюдаемых групп.
- Относительные пути и чтение CSV используют прежний safe_files, проверки
  обычного файла, размера, симлинков и границ workspace; FIFO не блокирует чтение.
  Общий deadline цикла B и атомарная запись answer.txt не менялись.

LLM-схема **не расширялась**: GROUP BY не представлен в штатном fallback,
его неподдержанная формулировка отклоняется до HTTP. Нельзя подсунуть
синтаксически корректную скалярную сумму вместо результата по группам.
Успешный групповой маршрут проходит через настоящий workflow openJiuwen,
сразу сохраняет answer.txt и не требует LLM даже при положительном BUDGET.

имеет меньший риск по безопасности и регрессиям. Работы по Search/Coding и C2
в этой сессии не начинались.
