# Цикл C3: статический Coding-пилот, 8 ноября 2026

Это отдельный review-only эксперимент. Он **не подключён к SOLVERS, workflow,
планировщику или конкурсному CLI**, выключен по умолчанию и исключён из образа.
Coding в безопасном production остаётся **0/32**. Конкурсные ответы DONE
в пилоте не создаются, исходники и тесты задач не изменяются и не запускаются.

## Исследование development

Изучены coding_solver.py, формат workspace, development coding_d01–d16,
предоставленные тесты как текст, текущий безопасный gate и независимый оценщик.
Ни один Python-файл задания не запускался и не импортировался.

- Арифметические return: d01 (3 балла, ошибочная операция), d02 (13, другая
  операция). Это два небольших модуля с функцией от двух аргументов.
- Ветвление/сравнения/границы: d03, d04, d05, d11; нужны семантика условий,
  циклов и/или доказательство требуемого поведения на границе.
- Вызовы и коллекции: d06–d10, d12–d13; нужен более широкий и рискованный язык.
- d14: очевидная синтаксическая ошибка, 13 баллов. Добавление двоеточия может
  дать parseable Python, но не подтверждает правильность функции или тестов.
- d15/d16: отсутствующий исходник/неполный workspace; не придумываем файлы.

Узкий AST-скан без контрактов распознал **2/16** модулей подходящей формы,
**12/16** вне поддержанного подмножества, один syntax_invalid и один source_missing.
Сумма rewards двух подходящих форм — **16 потенциальных баллов**, не earned points.
Для всех 16 результатов `contest_solution_confirmed=false`.
Никакой holdout для разработки этого пилота не использовался.

## Выбранный прототип

Новый `diagnostics/static_coding.py`. Внешний оператор обязан явно включить
`--experimental-static-coding`. Без него CLI завершается до чтения исходника.
Для предложения нужен **внешний проверенный контракт** add/subtract/multiply
и имя функции, заданные инженером, а не извлечённые из имени функции,
комментария или конечных примеров недоверенного теста.

Модуль допускает только определения обычных функций от двух аргументов,
с одним return и ограниченными арифметическими выражениями. Импорты,
декораторы, defaults, annotations, вызовы, attributes, классы, comprehensions,
циклы, globals и произвольный исполняемый код отвергаются. Код не выполняется
даже после прохождения фильтра. AST используется как структура данных.

Операторы в return меняются только по одному. Для кандидата строится
полином степени не выше двух; его коэффициенты сравниваются с независимым
внешним контрактом. Например, соответствие `x+y` проверяется алгебраическим
тождеством, а не двумя тестовыми точками. Это **условное доказательство только
для двух точных встроенных int**. Оно не распространяется на float, bool,
строки, контейнеры, пользовательские объекты, ресурсные свойства или весь
конкурсный контракт. Остальные функции не меняются. При нескольких подходящих
местах изменения или отсутствии кандидата предложения нет.

Исходный ошибочный оператор Division разрешён только для анализа/замены;
деление никогда не вычисляется и не принимается как полиномиальное доказательство.
Пределы: исходник 64 KiB, AST 256 узлов, глубина выражения 12, степень 2,
ограниченные целые коэффициенты. CLI использует существующий RuntimeLimits,
safe_files и чтение только workspace. Файловой публикации исправления нет:
предложение выдаётся в JSON-отчёт на stdout для ручного review.

`ast.parse` подтверждает только синтаксис. Дополнительное сравнение
коэффициентов подтверждает заданный внешний контракт, но **не доказывает**,
что этот контракт соответствует неизвестным требованиям конкурсной задачи.
Поэтому даже при `contract_proved=true` поля `independently_verified` и
`contest_solution_confirmed` остаются false; answer_created=false.

## Результаты собственных доверенных сценариев

| Сценарий | Результат |
| --- | --- |
| Вычитание вместо сложения, внешний add-контракт | Одно предложение с условным доказательством |
| Деление вместо умножения, внешний multiply-контракт | Одно предложение с условным доказательством, без вычисления деления |
| Уже правильное сложение | already_conforms, без предложения и без DONE |
| Ошибка константы | Нет подтверждённого исправления одним оператором |
| Два эквивалентных места изменения | ambiguous_or_no_repair, не выбираем произвольно |
| Синтаксическая ошибка | syntax_invalid, не выдаётся за правильное исправление |
| Декоратор с потенциальным побочным эффектом | unsupported_source, не выполняется |
| Нет внешнего контракта | missing_independent_contract, операция не угадывается |

Восемь сценариев: **2 условно доказанных предложения**, одно already_conforms,
два отказа по отсутствию/неединственности ремонта, syntax_invalid,
unsupported_source и missing_independent_contract. Это не 2 конкурсных решения.
Независимо подтверждённых исправлений реальных development-задач: **0**.
Python-фрагменты не исполнялись даже для оценки предложений: использованы
только собственные AST/алгебраические проверки и заранее доверенные fixtures.

15 unit-тестов прошли. Проверены границы полиномов и типов, неугадывание
контракта, ложные совпадения, неподдерживаемый код, default-off, read-only CLI,
отсутствие answer.txt и изменений исходника, traversal/симлинк/FIFO, запрет
subprocess и импорта модулей задач. Стандартный ast.walk импортирует доверенный
collections, это не импорт исходника задания; тест учитывает это различие.
Финальные WSL/Docker результаты приведены в сводке сессии.

## Почему production-включение отложено

Конкурсная инструкция требует «исправить, пока проходят тесты», но не задаёт
доверенный полный арифметический контракт и домен входов. Конечные примеры
тестов совместимы с бесконечным числом функций; имена вроде product не являются
доказательством. Не запускать тесты безопасно, но это не независимая оценка DONE.
Существующий benchmark справедливо считает DONE без независимой проверки
unverified, а не correct. Оценщик и его политика не менялись.

Для будущего включения потребуются отдельно разрешённые контрактный формат,
источник доверенной спецификации и независимый grading-контур. Необходимо
проверить полный домен входов, политику публикации и отказов, workflow,
security review и новые регрессии. Этот пилот не обходит отсутствие namespace,
не строит песочницу и не снимает существующий trusted-code gate.

## Запуск только на собственной синтетической задаче

```bash
.venv/bin/python -B -m diagnostics.static_coding \
  --experimental-static-coding --task-dir /tmp/own-synthetic-task \
  --source demo.py --function combine --contract add
```

Файл должен быть `/tmp/own-synthetic-task/workspace/demo.py`. Команда только
печатает review-отчёт. Нельзя подставлять внешний контракт из недоверенного
текста автоматически или использовать этот режим как конкурсный решатель.

Артефакты: `/tmp/harness-c2-c3-mhl1hitf/static-development.json`,
`static-synthetic.json`, `static-final-tests.log`.

Финальная проверка сессии: WSL 457/457, Docker 457/457; образ sidim-bez-dim:reserve-20261109-c2, 976MB.
