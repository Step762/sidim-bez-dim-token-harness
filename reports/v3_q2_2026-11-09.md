## 5. Первая реализация: точное half-up

`math_solver.py` распознаёт полную форму
`Round -8.125 to two decimal places using round-half-up.` и выдаёт `-8.13`.
Литерал — знаковое конечное десятичное число, precision0–100 (цифры или zero–twelve).
Режим обязателен. Значение разбирается в Fraction, масштабируется на10^precision,
целая часть и остаток сравниваются точно. Ровно половина округляется от нуля,
включая отрицательные числа. Float, eval/exec и произвольный Python не используются.

Сохраняются ограничения инструкции8000, литерала80 и размера рационального числа.
Выход — прежнее каноническое число без дополнения конечными нулями, отрицательный
ноль превращается в0. Внешние штатные output directions допускаются как прежде.
Без режима, с half-even, неизвестной/чрезмерной точностью, дробью1/3 или выражением
вместо литерала, научной записью и дополнительной командой задача пропускается.
LLM-схема не расширяется: скалярный unrounded-план не доказывает округление.

До реализации новые позитивные проверки воспроизвели отсутствие поддержки.
После —19/19 целевых Math-проверок. Отдельная первая точка: **46/0/82,267/503**,
development28/64,188/287; Math13→14,Data18,Search14,Coding0. Holdout без изменения.
Фиксированные пары4/20 и9/20, новые независимые контроли4/8 правильных,1/4 полных.
После этой контрольной точки Math-правила больше не менялись.

## 6. Вторая реализация: потоковый CSV top-1

Поддержанная полная форма:
`In ranks.csv, sort by score descending and label ascending to break ties. Return the label of the first row.`
Также Using; оба направления ascending/descending, необязательное numerically
для первого ключа, явное lexicographically для второго. Имена файла, трёх полей
и направления берутся из инструкции, а не из ID, известного SKU или ответа.

Первый ключ — корректное десятичное число, второй — строка. Без явно заданного
лексикографического порядка допустим только печатный ASCII с буквами в едином
регистре, без внешних пробелов. Numeric ID, mixed case и Unicode требуют слова
lexicographically: тогда используется точный порядок строк по Unicode code points,
без locale/natural-sort. Иное толкование не выбирается молча.

`csv.reader(strict=True)` проходит таблицу один раз. Хранится только лучший ключ,
возвращаемое значение и флаг неоднозначности: O(n), без сортировки всех строк.
Если все ключи победителей совпадают, а выводимые поля различаются — отказ.
Одинаковый вывод при полной ничьей допустим; порядок исходных строк не решает tie.
Более удачный последующий ключ сбрасывает неоднозначность проигравшей группы.

Проверяются все строки, в том числе проигравшие: форма, задействованные числа,
метки и вывод. Числовой литерал≤80 символов, вторичная метка≤512. Пустые таблицы,
пропуски, повреждение, отсутствующие поля и повторённый sort-столбец отвергаются.
Нельзя добавить фильтр, третий ключ, формулу, DISTINCT или другой результат и
получить ответ как будто инструкция была проще. Возвращается точное исходное
значение выбранного поля. Чтение только через прежний safe_files.open_text,
с ограничением CSV64MiB, отказом для symlink/hardlink/FIFO и traversal.

Math14,Data19,Search14,Coding0. Улучшения относительно Q1 — толькоmath_d09 и
data_analysis_d13. Локальный top-1 не включён в LLM-схему агрегатов: модель не
может подставить SUM/COUNT вместо запрошенной сортировки.
