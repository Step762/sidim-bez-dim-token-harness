## Реализация

В существующий `diagnostics/fallback_pilot.py` добавлен отдельный режим `--search`.
Он разрешает только development `search_d15`, модель
`qwen3.6-35b-a3b-noreason`, max_tokens512, HTTP timeout20с и один новый запрос.
Старый Math pilot, его состояния и проверки A1/A2 не ослаблены. Новый режим —
отдельно разрешаемый эксперимент; он не создаёт успешную квитанцию A1/A2.

Использованы существующие `run_tasks_diagnostic`, Trace/DiagnosticGateway,
BudgetManager, state_directory/write_once, output_files и настоящий workflow
openJiuwen. В cycle_a добавлен закрытый Search-маршрут с общим историческим
менеджером; строгая проверка модели/reasoning включена. Шлюз по-прежнему без
retries/redirects. Предельный estimate_input2000 проверяется также непосредственно
перед запросом, не только при предварительной подготовке.

История восстанавливается из подтверждённых командой usage35/11,53/7,181/111:
155.9 уже списано, из900 доступно744.1. Это доверенные исторические числа из
задания, не новая квитанция провайдера; старые private-state каталоги не читаются
и не записываются. Новая история не сбрасывает третье списание129.1.

Резерв текущего контекста1823/10+512=694.3; история плюс полный резерв850.2.
При максимально допустимом estimate_input2000 резерв712, вместе с историей867.9.
900 — жёсткий локальный лимит. Эвристика входа не является доказанным tokenizer
bound; нарушивший контракт сервер может сообщить перерасход. Он учитывается,
менеджер замораживается, следующих запросов нет. Абсолютная гарантия удалённого
списания или текущей квоты этим офлайн-этапом не подтверждается.

## Одноразовое состояние и ошибки

Новый фиксированный каталог `diagnostics/.search-pilot-state/` исключён из Git.
Каталог0700, intent/result0600. До workflow создаётся
`search_d15.intent.json` через O_EXCL/O_NOFOLLOW; fsync файла и каталога завершается
до возможного HTTP. Частичный файл или ошибка fsync не допускают HTTP; существующее
имя блокирует повтор. Одновременные процессы не могут занять один intent дважды.
Новый output-путь не освобождает попытку. Старые A1/Math-журналы не затрагиваются.

При timeout/API-ошибке/неизвестном usage сохраняется неизвестный резерв и frozen
ledger; confirmed_cost нового запроса=null, не0. При обрыве процесса без результата
intent остаётся и запрещает повтор. Нельзя удалять/сбрасывать состояние.
`--recover` читает durable result либо сообщает uncertain без повторного HTTP
и без чтения ключа. Повреждённый/неузнаваемый state требует ручной проверки.

Результат включает HTTP/JSON, независимую оценку плана, решение валидатора,
исполнение, answer/grade, finish_reason, usage, новый/суммарный расход и время.
В отчёты не записываются ключ, Authorization, prompts или сырой ответ модели.
Отдельное output-хранилище сохраняет report.json/report.md0600 и, при успехе,
настоящий tasks/search_d15/answer.txt0644. Ошибка записи внешнего отчёта не разрешает
повтор: прежде следует использовать сохранённый result через recover.

## Команды подготовки и одного будущего запуска

Сначала получить свежую passing offline-квитанцию текущей диагностики (старая
квитанция Q3 Mini после изменения source fingerprint не подходит):

```bash
umask 077
search_review=$(mktemp -d /tmp/search-pilot-review.XXXXXX)
timeout 180s .venv/bin/python -B -m diagnostics.cycle_a \
  --mode offline --output "$search_review/offline"

BUDGET=900 .venv/bin/python -B -m diagnostics.fallback_pilot --search \
  --offline-report "$search_review/offline.json"
```

Будущая LIVE-команда — **не запускалась; только после отдельного разрешения**.
LLM_BASE_URL/LLM_API_KEY должны поступать через окружение разрешённого аккаунта;
значения не печатать, не передавать аргументами и не писать в проект.
Endpoint должен совпадать с ранее разрешённым NeuralDeep BASE_URL. Это не
подтверждение эквивалентности конкурсному прокси или доступности модели сейчас.
Output должен быть новым; его создаёт сам pilot.

```bash
BUDGET=900 timeout 120s .venv/bin/python -B -m diagnostics.fallback_pilot --search --live \
  --offline-report "$search_review/offline.json" \
  --output "$search_review/live-search"
```

После успеха, ошибки или обрыва анализировать без нового HTTP:

```bash
.venv/bin/python -B -m diagnostics.fallback_pilot --search --recover
```
