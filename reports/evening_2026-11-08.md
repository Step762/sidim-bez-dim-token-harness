## Что исправлено и как проверено

До вечернего исправления тест воспроизвёл дефект: синхронное исполнение
fallback занимало 0,467 с при лимите 0,04 с. Внешний `asyncio.timeout`
не мог прервать синхронную работу, блокировавшую event loop.

Минимальное исправление: общий `RuntimeLimits` передаётся в fallback;
синхронные `prepare`, разбор внутреннего JSON и проверка/локальное исполнение
плана обёрнуты в сигнальный таймер. Через `await` сигнальный таймер не переносится.
Таймаут классифицируется как `timed_out`, без повторного платного запроса.
Семантика валидатора, решатели, сетевые ограничения и формула бюджета сохранены.

13 целевых тестов времени прошли за 2,794 с. Проверены:

- прерывание sleep и CPU-цикла, восстановление обработчика SIGALRM;
- продолжение остальных задач после зависшего локального решателя или preflight;
- ограничение синхронного исполнения fallback после подтверждённого usage;
- отмена зависшего mock HTTP с сохранением uncertain reserve и заморозкой бюджета;
- общий дедлайн с сохранением ответа предыдущей задачи;
- сохранность прежнего `answer.txt` при прерывании записи и уборка своего temp-файла;
- изоляция ошибки записи, неизвестного типа и незавершённого workflow.

## Часовой лимит

Production CLI отсчитывает монотонное время от начала `main`: по умолчанию
3540 с, запас 60 с до внешнего конкурсного часа. Отдельная синхронная операция
и workflow ограничены 30 с; HTTP имеет собственный timeout 20 с.
`--time-limit` разрешает уменьшить общий срок, увеличивать выше 3540 с нельзя.
`--operation-timeout` задаёт лимит операции, ограниченный оставшимся общим временем.
Сохранение ответа выполняется сразу после решения и атомарно, рядом с `task.json`.

Проверка выполнялась короткими реальными таймерами, без ожидания полного часа.
Это ограниченная по времени синхронная работа в главном потоке Linux, а не
фоновое исполнение: event loop может быть занят до срабатывания лимита.
Для непрерываемого ядром I/O, задержки Python signal handler в стороннем C-коде
и неисправного окружения остаётся нужен внешний supervisor. Официальный внешний
часовой timeout не отменён. Новая изоляция coding не заявляется.
