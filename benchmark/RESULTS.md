# V2 №5: результаты независимого benchmark

Версия diagnostic-128-v1. Исполняемый код агента соответствует коммиту 1219d05; решатели, планировщик, BudgetManager, gateway, fallback и семантические проверки не менялись. Все цифры ниже относятся к синтетическим задачам.

## Набор и независимость

128 задач: по 32 каждого типа, 64 development и 64 holdout. В каждой выборке по 16 задач каждого типа. Seeds 20261105 и 20261106. Имеют определённый эталон 104 задачи; 24 требуют отказа. Всего назначен 611 балл, из них 503 относятся к задачам с определённым результатом и 108 — к неразрешимым/неоднозначным случаям.

Эталоны не извлекались из production-кода. Арифметика рассчитана отдельно, CSV — независимыми SQL-запросами и точными числами, coding — отдельными примерами функций. Входные task.json не содержат expected/check. Политики равенства и ограничения авторского holdout описаны в README этого каталога.

Семь доступных fallback-запросов — слишком малая нагрузка для общего вывода о планировщике.

Пример невыгодного по баллам fallback: math_h15 даёт 0 reward и стоит 108.1 mock-единицы. Это не рекомендация всегда отбрасывать нулевую награду: в отборочной паре требуется решить обе задачи.

## Проверки и ограничения

Все 128 задач режима A проверены внутри настоящего образа sidim-bez-dim:harness-v2-math: совпадение ответов и статусов с host, 40 верных, 0 неверных, 88 пропусков, 217 баллов; wall 19.960 с. Эталоны в контейнер не монтировались. Режимы B–E проверены на host. Docker использует read-only, tmpfs 2 ГиБ, cap-drop ALL, no-new-privileges, network none, 16 ГиБ RAM, 8 CPU, 512 процессов.

Все прежние 299 тестов и 15 новых дают 314/314 на host за 143.827 с и 314/314 в Docker за 333.119 с. После окончательных правок оценщика его 15 тестов дополнительно прошли на host за 51.664 с и в Docker за 118.762 с. Официальный CLI совпал с worker по всем 128 ответам/пропускам. Машинные результаты проверок сохранены в results/validation.json.

Первый полный Docker smoke превысил 300-секундное ожидание тестового драйвера. Повтор с ожиданием unit-тестов до 600 с завершился успешно; ограничения контейнера и таймауты coding не ослаблялись. Восемь официальных примеров сохранили 6/8 безопасно и 8/8 с явным доверием только к предоставленным coding-примерам. Образ остался 976 MB; все 15 runtime-файлов совпали с HEAD 1219d05. Все 199 файлов codex-local неизменны, git diff --check прошёл.

При окончательной проверке оценщика устранено смешение JSON true и 1; политика также различает 1 и 1.0. Все сохранённые сырые ответы переоценены по окончательной политике: ни один статус и балл не изменился. К отчётам добавлены проверенные SHA-256 runtime, чтобы resume не использовал результаты другой версии агента.

Публичные grading-эталоны и отчёты не входят в образ. Стандартный coding остаётся выключенным; trusted-прогон новых coding-задач не выполнялся. Даже будущая изоляция не обещает получить все 131 coding-балл: возможности генератора исправлений отдельно ограничены. Для будущего безопасного исполнения нужен отдельный независимо проверяемый grading-контур; DONE без него имеет статус unverified и 0 баллов. Бенчмарк не измеряет масштабируемость больших файлов, настоящую точность LLM или реальную токенизацию.

## Вердикт и рекомендации

Диагностический этап V2 №5 реализован: набор и оценщик воспроизводимы, результаты неудобных сценариев сохранены, продукционное поведение не подгонялось. Агент пока нельзя считать готовым к произвольному отборочному прогону. К следующему этапу автоматически не переходим.

1. V2 №6: расширять бесплатный семантический разбор обычных формулировок math/search/data_analysis на development, включая уже проверяемые fallback-схемы. Это сокращает очевидные пропуски и семь модельных вызовов; подтвердить эффект отдельным holdout после фиксации изменений.
2. V2 №7: добавить ограниченные операции CSV и аккуратное объединение KB-фактов с проверкой противоречий. На этом синтетическом наборе здесь значимая часть потерь; для coding вести отдельное исследование изоляции, не ослабляя безопасный режим ради баллов.
3. V2 №8: повторить независимые пары, Docker и бюджетные аварии на более широком фиксированном пуле. Проверять выигрыш планировщика на нескольких бюджетах и сохранять отрицательные результаты; расход настоящего прокси измерять только после отдельного разрешения.
